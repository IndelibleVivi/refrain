# Architecture

Status: source architecture for the current experimental line. See [current state](current-state.md) for implementation and acceptance boundaries. Planned capabilities remain in [the roadmap](ROADMAP.md).

## Authority chain

![Host-authored music travels through a stateless compiler into a portable artifact, shared Canvas, and explicit exports](diagrams/architecture.svg)

[Editable Mermaid source and evidence map](diagrams/README.md). The overview includes both the conversational MCP route and the local tool + Skill workflow. Private conversation remains host-side; only authored music, deliberate captions, and exact musical artifacts enter Refrain.

AIR and its musical receipt own music and continuity. `PerformanceBinding` is associated beside AIR in an invocation, result, or artifact; it never enters AIR or `sourceRevision`. `PerformancePlan`, audio, MIDI, visuals, transport, caches, and render receipts are derived. No projection may become the only copy of musical intent.

## Object contracts

- **AIR** owns title, conductor time, meter map and pickup, motifs and transforms, harmony, reusable phrases and techniques, explicit groove and tuplets, form, voices, carried authoring vocabulary, stable instrument identities, roles, register, rhythm, dynamics, articulation, ties, pan, and ending. It does not own vendor patches, asset URLs, sample hashes, microphone choices, browser caches, or DSP graphs. AIR@1 is current; AIR@0 is an exact historical/migration boundary.
- **CompiledAir** is the deterministic local expansion with stable section/phrase/segment/motif anchors, notated and performed onset, realized segments, normalized motif material, diagnostics, conductor schedule, and events. Expanded events remain local and must not become the ordinary model payload or URL envelope.
- **Musical receipt** binds source identity, logical air identity, lineage, and verified relation evidence. Shape validation is separate from one synchronous higher-level integrity authority that verifies `evidenceId`, root/lineage status, logical-air semantics, and `receiptId`; portable and presentation import additionally bind the parsed canonical source to `sourceRevision`. Its exact serializers remain `canonicalAirJson`, verification-core JSON, and `receiptIdentityJson`. AIR@1 reconstructs every closed nested object's field order at those hash boundaries, so JSON object-key insertion order may change in transport without changing identity; array order remains identity-bearing. It does not prove an audible render.
- **Instrument vocabulary** owns model-facing identity, family, authored range, supported percussion notes, and authoring meaning only.
- **AuthoringVocabularyClosure** is the exact immutable instrument/technique vocabulary carried by AIR@1 and supplied to one compile. It may close over core definitions plus exact ExtensionPack@1 authoring modules. Installed-pack state never changes it implicitly; its content identity enters source interpretation without making local pack state canonical.
- **ExtensionPack** is a local distribution envelope for independently digest-addressed typed modules and exact assets. ExtensionPack@0 retains the historical execution modules; ExtensionPack@1 may additionally contribute one exact `authoring-vocabulary` module. Container identity proves packaging only. Installed metadata, hydrated bytes, active authoring shelf, archive pins, and one AIR-plus-binding execution closure are distinct local states and none enter AIR identity.
- **Candidate shard** owns one exact implementation: assets, engine/mapping, calibration, regions, articulation and velocity coverage, candidate-scoped round robin, loop/release, processing history, provenance, rights, and release state. Storage is one immutable content-addressed shard per candidate plus a lightweight routing catalog; the former monolithic implementation manifest has no runtime or tracked compatibility path.
- **SoundProfile** chooses exact candidate chains for an explicitly declared vocabulary subset through direct `{ id, sha256 }` pins. `SoundProfile@1` remains the strict all-core historical form; `SoundProfile@2` is closure-scoped and a binding must prove coverage for every identity used by its AIR. Whole-identity fallback is the only fallback mode.
- **RenderScene** is the authored, versioned production environment. Historical `RenderScene@0` executes master gain, peak ceiling, and velocity scale. `RenderScene@1` is a bounded declarative acyclic bus graph with explicit routing and core-owned gain/placement, filter/EQ, saturation, delay/room, and fade/tail processors. Packs supply exact data and assets, never executable DSP or arbitrary plug-ins; parameters, seeds, feedback, graph depth, and tails are validated.
- **PaletteRecipe** is a discoverable set of exact module references that resolves once into a closed `SoundPalette`; playback never consults a mutable recipe or installed-pack preference.
- **SoundPalette** is the human/agent creative unit combining an exact profile, exact scene, authoring guide, descriptors, strengths, constraints, and intentional contrasts. It is not an inferred genre taxonomy.
- **PerformanceBinding** names exact profile, scene, optional palette, allowed overrides, renderer contract, and compatibility facts for one AIR embodiment. One AIR may have several bindings and one artifact may designate a default. Historical validation proves the embedded closed contracts and digests without consulting mutable current catalogs; runtime resolution separately reports exact availability against the installed vocabulary, exact candidate shards, and renderer.
- **PerformancePlan** is the fully resolved execution contract. Historical renderer bindings retain strict `performance-plan@2-experimental` behavior. Complete-piece renderer bindings use compact `performance-plan@3-experimental`: exact binding/profile/scene/palette/renderer authority, compiled identity, voices, event-to-resolution indexes, deduplicated sample attacks, candidate/region/RR/loop/release facts, first/last asset use, and exact required assets. It does not embed a second `CompiledAir` or a second event schedule.
- **ExecutionBundle** seals one local `CompiledAir`, its digest, one complete-piece plan and digest, runtime-only asset locators, and typed frame indexes/checkpoints. It is the adapter entrypoint; adapters do not independently resolve music or sound.
- **PreparationPlan** is a separate derived loading policy: opening closure, ordered first-use/deadline facts, bounded fetch/decode concurrency, and decoded-cache budget. It can change operational preparation without changing musical, binding, or plan identity.
- **ResolvedRenderProfile** is internal data derived only from the exact scene plus permitted binding overrides. Authored `RenderProfile` input has been retired and must not return as a competing gain/ceiling authority.
- **RenderReceipt** binds source, compiler/resolver/renderer contracts, binding/profile/scene/candidate/plan digests, bytes actually verified, adapter facts, output amplitude policy, adaptations, and exact output digest where bytes exist. Imported receipts re-run the constructor's semantic invariants; recomputing an ID cannot legalize a missing verified-byte closure or contradictory WAV/MIDI policy.
- **RefrainArtifact** contains AIR, its same-generation musical receipt, caption, zero or more bindings, and optional render receipts/projection references. Its provenance graph requires every receipt to resolve to an embedded binding and every projection kind to agree with its receipt and output digest. AIR@1 exports use Artifact@3; strict Artifact@0/@1/@2 readers preserve their historical AIR@0 contracts.
- **ListeningReport** is a non-mutating projection with separate structural and embodiment diagnostics. It records observable density, register, attack, recurrence, silence, peak/headroom, clipping, and scene-tail facts without an aggregate quality, pleasantness, genre-fit, or intimacy score.

## Package boundaries

- `identity` owns the single synchronous browser-safe, cross-runtime SHA-256 primitive used for deterministic text identities. It owns no AIR, receipt, sound, or presentation serialization policy.
- `air-schema` owns strict model-writeable AIR@1 syntax, exact AIR@0 historical parsing/migration, vocabulary-closure identity, rational/conductor/groove/phrase/technique guards, and version dispatch—not musical taste.
- `compiler` owns deterministic versioned lowering, conductor and meter scheduling, harmony, explicit transforms/techniques/groove/tuplets, expression, ties, stable section/phrase/motif anchors, normalized source-ordered motif material, events, and diagnostics. Every AIR@1 compile consumes its explicit immutable authoring-vocabulary closure; it never reads an ambient pack registry.
- `soundpack` owns the core instrument vocabulary, ExtensionPack@0/@1 module manifests including exact authoring-vocabulary modules, local pack lifecycle and archive pins, the candidate catalog/shards, direct-pinned profiles, scenes, recipes and resolved palettes, deterministic build-time SFZ and synth-family compilers, provenance, and their validators. Vendor SFZ interpretation belongs at build time, never runtime; unsupported sound-affecting opcodes fail closed.
- `audio-engine` owns binding resolution, historical plan compatibility, current complete-piece plan/index/preparation authorities, candidate-local RR, verified asset loading, atomic projection of one exact AIR-plus-binding closure, sampler/synth execution, bounded scene DSP, progressive preparation, transport reconstruction, transferable block render, MIDI adaptation, render evidence, and deterministic listening-report projections.
- `renderer` owns bounded `refrain-structure@1-experimental` whole-form visual facts, explicit detail windows, exact selection, versioned canonical source/receipt/evidence identity serializers, Receipt@1 relation and embodiment integrity, exact presentation-reference bytes, synchronous Artifact@0–@3 helpers, local appearance validation/storage, exact Easy Share policy, and one shared source-to-view implementation. `AirRenderer` remains the React authority for artifact/audio/export/selection/share effects; `selen-v21-model.ts` adapts exact compiled/source facts into explicit visual lanes; `SelenV21Canvas.tsx` only mounts and updates the imperative product runtime; and `selen-v21-runtime.ts` retains the four distinct Selen composers without re-expressing their SVG geometry in JSX. Paper Sonata is the default local theme. High motif density suppresses non-landmark marks only in the whole-form figure while retaining every exact anchor in the bounded selection/list surface. Whole-form density is at most 192 bins per voice; structure anchors and detail events have separate caps. The package must not create one DOM node per compiled event at piece scale or depend on Node-only crypto or MCP/server code.
- `mcp-server` presents one stateless `hum` action and a read-only App resource. Its `tools/list` schema always describes the implemented contract, never an aspirational future shape.
- `presentation` owns inline/session/file delivery shells, the first-listen playlist and exact public-demo manifests, and export/import CLI over shared packages. A session locator is high-entropy, operator-scoped, expiring delivery state with typed missing/expired results and identity revalidation; it is never continuity authority. A public catalog locator is valid only when its artifact ID and SHA-256 match bytes already built into that exact receiver.
- `soundbench` is the internal audition, provenance, performance, and listening-evidence consumer, not the production Canvas.

## Sound integrity and loading

Every runtime path uses one verification boundary:

```text
asset reference -> bytes -> byte-count check -> SHA-256 check -> verified cache -> decode/render
```

A same-length replacement must fail. Receipts bind the actual verified digest. Native-gain PCM/WAV preserves resolved amplitude; an audition-matched preview is a separate versioned transform. Deterministic RR uses stable authored attack order plus a candidate-scoped seed, so unrelated catalog changes do not alter an unchanged candidate.

Target content acquisition is selective by candidate, profile, palette, or AIR-plus-binding closure. A lightweight catalog points to immutable candidate shards; an ignored content-addressed store accepts exact verified bytes and atomically projects them into runtime paths. The CLI presentation derives the current AIR's `requiredAssets` from its selected exact binding and prepares that closure in a private temporary public directory owned by this preview. The Vite Node API starts the shared presentation shell on an available loopback port; session delivery uses that same origin. JSON output always selects a short session locator rather than returning artifact bytes inside a URL; text output retains inline delivery when it fits. Closing the preview removes its own temporary projection; concurrent previews do not replace each other's assets; it does not accumulate historical assets or bootstrap a fixed profile. There is deliberately no selector-free fetch-all path. Adding an unrelated candidate must not change an existing candidate/profile/scoped-closure digest or performance.

The pack manager requires an explicit operator root. Install validates and records metadata without fetching all assets; hydration verifies only requested exact asset closures; shelf activation changes discoverability only; archive pins prevent dishonest uninstall. Removing an unpinned pack removes its managed metadata and unreferenced hydrated projection, never user-authored AIR/artifact files or shared content-addressed bytes still referenced by another installed pack.

## Piece-scale execution

Whole-piece prerender remains a correctness/export reference, not the interactive path. `performance-plan@3-experimental` records first/last asset use; `PreparationPlan` derives opening closure and prefetch deadlines. Browser playback creates `AudioContext` only inside the explicit Play path, verifies and decodes the exact target closure with bounded concurrency, ensures the selected adapter is ready, then starts atomically at that target frame. Resume, playing seek, restart, and buffer recovery share that readiness invariant; resume/seek/restart/recovery also rebase active prefetch instead of leaving only reactive loading. Bounded scheduling supports pause/resume, stop, restart, seek, and section jump. Seek snapshots reconstruct active sustains, releases, loop/sample offsets, oscillator phase, and upcoming events without audibly replaying from time zero. Raw WAV bytes are released after decode, while base PCM and any full-buffer loop-crossfade projections share the decoded LRU accounting. Browser SoundFont state is reconstructed through the sequencer; direct synth reconstruction preserves event/envelope semantics but does not claim universal filter-history byte identity.

Offline reference rendering uses one deterministic block kernel across transferable browser-worker blocks and Node. Node WAV export writes bounded float blocks to a temporary first pass while measuring peak, then streams a RIFF/PCM second pass with the native or explicit matched amplitude policy; no whole-piece PCM array is allocated. Byte-exact reproducibility is claimed only for this pinned offline path. Browser realtime adapters owe semantic parity—events, note lifecycle, candidate, gain, loop/release, and scene facts—unless they explicitly emit bytes under that same pinned contract.

## Presentation and stateless continuation

For current AIR@1, Tier 0 returns one exact Artifact@3 plus compact summary, diagnostics, and runtime performance status; the artifact is the sole model-visible source/receipt/binding authority and expanded events stay local. Historical AIR@0 retains its exact top-level result projection. Tier 1 and Tier 2 import the same renderer and view model, and the MCP Canvas reconstructs directly from the same Artifact@3 instead of receiving a second full private result. One `application/vnd.refrain+json` byte sequence and SHA-256 identity travels through inline fragments, an exact public-build catalog locator, high-entropy expiring loopback sessions, file import/export, or MCP result delivery. The catalog path is zero-upload because the receiver already carries those exact bytes and verifies the hash in the link; it is not a mutable library lookup. Session responses are operator-scoped, no-store, origin-restricted, expiry-typed transport state; they are not continuity authority. Import revalidates the exact byte identity, musical-receipt integrity, and canonical source/receipt cross-edge before resolving exact performance against the current runtime. An unresolved historical binding leaves source, structure, selection, and canonical export available but disables playback; legacy artifacts require an explicit audible binding instead of acquiring a current default. Delivery limits never define musical scale.

Every continuation call supplies complete authorities for verification. Current AIR@1 passes the exact parent Artifact@3 unchanged; the server derives and cross-verifies its parent source, receipt, and binding, while legacy explicit fields remain accepted only as a compatibility input. Process-local caches may accelerate delivery or rendering but are not required continuity state. Relationship and conversation context remains inside the host runtime: it may inform authored music and caption, but `hum` does not accept, echo, hash, or store private context fields.

## Trust boundaries

- No server-owned user library, relationship profile, hidden model, or provider key.
- Refrain is operator-self-hosted. The reference HTTP container binds target-host loopback only; OpenAI Secure MCP Tunnel, when selected, is an outbound transport owned by the operator and does not become Refrain application state or a public origin.
- One MCP origin serves every connected host. ChatGPT, Codex, Kimi Code, and other adapters must not receive separate `hum` implementations, Canvas forks, or host-specific sound assets.
- Browser sound and selection-to-chat handoff each require an explicit user gesture.
- Browser-local appearance images stay in IndexedDB and object URLs. Easy Share may carry only validated scalar appearance unless a future explicit static-package flow includes a reviewed image derivative; the current link path never uploads or serializes the local Blob.
- Operator-configured output roots, asset roots, session stores, and public origins are explicit authorities.
- No unannounced external asset origin, arbitrary vendor-script execution, or silent fallback across identity, source, or rights boundaries.
- Third-party assets retain asset-level provenance and original terms.
- Public release requires separate license, rights, listening, clean-install, real-host, and explicit owner acceptance.

The canonical packaging, loopback systemd unit, tunnel profile, and host-acceptance sequence live in [runbooks/self-host-mcp.md](runbooks/self-host-mcp.md). A tunnel runtime API key authorizes the daemon to OpenAI's control plane; it is not an MCP OAuth token and never enters Refrain source, receipts, artifacts, logs, or repository configuration.

OpenAI Secure MCP Tunnel carries MCP JSON-RPC responses only; it is not a reverse proxy for iframe `GET` requests. The production `hum` resource surface therefore exposes exactly one explicit-version `ui://` App document, embeds the exact Vite JS/CSS build, and declares zero embedded Canvas network domains. The tool descriptor binds that one URI through standard `_meta.ui.resourceUri` plus ChatGPT's compatibility alias. ChatGPT file export is the sole external-navigation exception: after a user gesture, a non-mobile ChatGPT host with the complete `uploadFile` / `getFileDownloadUrl` / `openExternal` extension may send already-generated exact JSON to the declared ChatGPT file origin; the file is not added to the durable ChatGPT library. Mobile ChatGPT and other MCP hosts use standard `ui/download-file`. The resource requests standard `clipboardWrite`; only an available host-granted clipboard can carry exact JSON after a rejected download, and host policy may still refuse it. Runtime identity remains separate in `release.json`, OCI labels, `/healthz`, and private tool-result metadata; it is not a second discoverable resource or a build-derived query pointer. That MCP build retains the shared renderer, Selen UI, and transport state machine but excludes sampled/SoundFont adapters that cannot run without an asset plane. AIR whose exact execution closure contains only synth candidates can render and play through `direct-nodes@1`; the server advertises and applies exact `f-synthetic-beat@0` only as the default for an omitted AIR@1 binding. Server `performanceStatus` and renderer controls classify the same sealed plan against one shared zero-asset Canvas configuration, so any sampled closure remains exact but is marked unavailable before the model or person can mistake it for audible playback. Ordinary browser builds retain sampled playback.

## File-based agent authoring

`apps/presentation/src/authoring.ts` owns `draft` and local `hum` command orchestration. Drafting uses the canonical AIR vocabulary factory and only writes silent source; sealing calls the existing `humV1` and Artifact@3 factory. Local file inputs and outputs preserve the caller's working directory and reject overwrite. A new root visibly defaults to `f-synthetic-beat@0`; continuation inherits the parent's exact default unless explicitly changed, including custom bindings and unbound parents. Runtime selection availability remains separate from asset acquisition and playback.

`inspect-air.ts` compiles through exact version dispatch and checks artifact integrity through the portable parser. It reuses structural ListeningReport facts, reports bounded section/voice/occurrence detail, and compares note multisets separately from expression, instruments, roles, timing, and performance-binding identities. Authored sustains entering a section remain in that scope; rendered sample and DSP tails are not inferred. This inspection envelope is a CLI projection, not a new music or receipt format. The Plugin Skill routes the host through these operations without sending private conversation to the core. The deployed MCP grammar and single `hum` tool are unchanged.

`apps/presentation/src/production.ts` owns the local production authoring input and `produce init/inspect/apply` orchestration. Canonical scene/profile/binding factories seal its explicit choices; the artifact constructor retains prior authorities while selecting a new default. Source/base pins prevent stale settings, and effective master materialization leaves no competing override in the derived binding. `audio-engine/src/scene-routing.ts` owns the shared first-match predicate and bus-chain projection used by production inspection, WebAudio and offline execution. No DSP algorithm or historical format is widened.

The formal `refrain mcp stdio` command runs the same server factory in production mode from its package root, so the self-contained Canvas resolves independently of the caller’s working directory. `npm run build:mcp-host` is the explicit first-use prerequisite; a missing manifest produces that instruction. The direct source entry remains usable by development contract tests; it is not the documented host-install path.

The shared renderer owns English/Chinese interface copy and the language switch. Locale stays outside AIR, receipts, bindings, and visual facts. The React audio owner persists while the same Selen composer redraws its interface text; open passage controls and focus are retained for the same artifact. Both URL and MCP wrappers use that implementation.
