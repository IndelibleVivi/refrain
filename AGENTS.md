# Refrain agent contract

Read `SPEC.md`, `docs/PRODUCT.md`, `docs/ARCHITECTURE.md`, and `docs/ROADMAP.md` before changing programme order or public contracts.

## Authority and boundaries

- Project naming is `Refrain` / an `air` / `hum`; **Refrain hums an air.** is shared across English and Chinese. `packages/renderer/src/ui-copy.ts` owns interface prose; language is local presentation state, never musical identity. Preserve authored text and exact names; do not invent a Chinese product name or a second localized renderer.
- `air@1-experimental` is the canonical music source for the current development line. AIR@0 remains an exact historical reader and explicit migration input, not a second active grammar. Compiled events, MIDI, WAV, visual layouts, and browser state are projections.
- The current host agent chooses musical expression. Compiler code may normalize notation, expand explicit transforms, enforce ranges and safety, and emit warnings; it must not silently rewrite music for taste.
- Keep the core stateless. Do not add user accounts, OAuth, hosted relationship memory, an official work library, or a hidden composition model.
- Refrain remains self-hosted rather than a Refrain-operated backend. The canonical private OpenAI path is one loopback HTTP origin plus an operator-owned outbound Secure MCP Tunnel; do not expose the origin publicly, copy another product's OAuth issuer, or fork one deployment per host.
- Relationship context remains host-side and may inform the authored air and optional caption. `hum` must not accept, echo, hash, or store private conversation context.
- Production Canvas aesthetics come from the Faye/Selen-approved visual-research line. The active private G candidate is the selective Selen v21 transplant in `packages/renderer`; preserve that source authority and do not redraw the composers from screenshots or restore the retired generic density-lane UI. The soundbench remains disposable functional engineering UI.
- Tier 1 URL and Tier 2 MCP Canvas must import the exact same renderer package and preserve one visual-language contract. A host adapter may wrap it but must not fork product UI.
- Audio never auto-plays in chat/browser surfaces. A user gesture starts playback. Device-authorized autonomous playback is a later, separate integration boundary.
- Sound assets require asset-level provenance. A package license does not determine the license of bundled samples.
- Project-original functional materials use SUL-1.0; authored content and example music use CC BY-NC-SA 4.0. `LICENSING.md` owns the path-level scope; preserve all third-party terms and never call this OSI open source. Changing the selected licenses or their scope requires owner confirmation.

## Verification

Run `npm run check`, `npm run cli:smoke`, `npm run audio:smoke`, `npm run mcp:smoke`, `npm run selection:smoke`, and—after a build—`npm run mcp:http-smoke` for shared contract or CLI changes. Sound-candidate or amplitude/receipt changes additionally require `npm run soundpack:catalog`, explicit selective acquisition with `refrain fetch --candidate <id>` or the retained npm-script selector, `npm run listening:packets -- --out=tmp/g3b-listening-packets`, and `npm run listening:verify`; packet generation is mechanical evidence, never listening acceptance, while the strict verifier must fail if a Faye-accepted candidate/fallback digest, receipt identity, or asset/candidate closure no longer reproduces. Run `npm run export:repro-smoke` for exporter, offline audio, plan, serializer, or receipt changes. Confirm that historical audition-matched decisions reproduce separately from native-gain export. Identity-primitive or serializer changes require fixed-ID and Node/browser-primitive parity tests for `canonicalAirJson`, verification-core JSON, and `receiptIdentityJson`. Inspect candidate required-asset closure and exact digest-bound prior decisions after any candidate-shard or profile hash change. Correspondence changes require exact full/clip PCM, A/B target alignment, selective share/receive integrity, declared response basis, complete-parent fresh-process reply, and actual stdio/HTTP audio-content tests. Named-host model audio input remains separate acceptance. MCP schema/portability changes require `tools/list` size/reference assertions and fresh-process continuation evidence. Parser/compiler changes require focused fixture tests. Audio/UI changes require real browser playback checks in addition to build success.

MCP App resource, host bridge, capability-aware export, selection return, or renderer lifecycle changes additionally require `npm run test:mcp-host`. That local Chromium lane proves only the exact self-contained App and declared observable host profiles; it never proves the Secure MCP Tunnel, deployed revision, undocumented ChatGPT behavior, workspace policy, Faye/Selen acceptance, or owner acceptance.

Runtime packaging, release identity, container, systemd, or tunnel changes additionally require the process-level tunnel preflight regression plus a clean committed-tree `npm run mcp:package -- --out=<new ignored path>` proof; inspect `release.json`, the packaged preflight helper/service pair, materialized OCI labels, exact `/healthz`, the private tool-result release metadata, and the one-resource App discovery contract. This is candidate evidence only and never authorizes installation, image activation, tunnel restart, or live deployment.

AIR@1 source/receipt/artifact changes additionally require the five-fixture `fixtures:air-v1` corpus, AIR@0 migration tests, strict any-version dispatch failures, mixed-meter MIDI/export integration, missing-extension-sound behavior, and an exact Artifact@3 desktop/mobile user-gesture playback check. Corpus diversity is implementation evidence, not independent model authorship, genre quality, or listening acceptance.

Extension-pack, sparse-profile, scene@1, Binding@1, plan@4, receipt@3, artifact@2, or local-manager changes additionally require `npm run packs -- proofs`, pack lifecycle/shared-byte tests, the vnext presentation export integration test, repeated offline DSP equality, and real browser playback of an exact Artifact@2. Pack proof success is engineering evidence, never listening or release acceptance.

F candidate/palette changes additionally require `npm run f:palette-packets -- --out=tmp/f-palette-packets --render-stress`; its native, matched, and stress renders are mechanical evidence only, and `pending-faye` must not be promoted by a passing command.

Complete-piece scale, plan, renderer, transport, delivery, or bounded-render changes additionally require `npm run tranche:d:evidence -- --render-all` against both checked-in complete-piece fixtures and real-browser checks of explicit-play startup, pause/resume/stop/restart, seek/section jump, looped-sustain reconstruction, desktop/mobile overflow, keyboard controls, no pre-gesture asset fetch, and console cleanliness. Evidence under `tmp/` and browser screenshots are local QA artifacts, not tracked product assets.

Keep `.github/workflows/ci.yml` path-unfiltered so the `core-contracts`, its focused `mcp-host-browser` dependency, and `clean-production` checks always appear on pull requests and `main`. Sound content cache is only a performance projection: cache `apps/soundbench/public/soundpacks`, key it from the catalog plus immutable candidate shards, and still run an explicit profile-targeted `soundpack:fetch` to re-verify byte count and SHA-256. The separate sound-evidence workflow may be path-filtered because it is not a required check. Keep workflow permissions read-only and third-party actions pinned to reviewed full commit SHAs.

Update `docs/current-state.md` when implementation, candidate, runtime-tested, or live status changes. Do not describe a candidate soundpack, renderer, MCP host, or export path as accepted before its corresponding evidence exists.
